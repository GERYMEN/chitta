D-a Input = APPROVED, non-transfer SPEND rows only (reuse the isSpendRow /
    spendContribution rule; exclude transfers, pending, rejected, income).
    Group by normalizeMerchant(merchantName).
D-b A group is RECURRING when it has >= 3 occurrences whose consecutive gaps
    cluster to a cadence: weekly (7d), monthly (~30d, accept 28..31), or yearly
    (~365d), each gap within a tolerance of its cadence; AND the amounts are
    within +/-10% of the group's MEDIAN amount. Groups that are irregular, too
    few, or too varied in amount are NOT recurring.
D-c nextDueAt = lastOccurrenceAt + the median gap (snapped to the cadence).
    "Upcoming" = nextDueAt within the next 14 days from now (useNow), including
    a few days overdue (nextDueAt from (now - 3d) to (now + 14d)) so a just-
    missed one still shows.
D-d Pure helper in src/domain/recurring/: detectRecurring(transactions, now)
    -> RecurringSeries[] { merchantKey, displayName, cadence
    ('weekly'|'monthly'|'yearly'), typicalAmountMinor (median), lastAt,
    nextDueAt, occurrenceCount }. A second pure helper upcomingWithin(series,
    now, windowDays) -> the ones due in the window, sorted by nextDueAt. NO side
    effects, NO clock read inside (now passed in).
D-e Home "Upcoming" card (new, src/features/upcoming/ or /recurring/): shown
    ONLY when >= 1 upcoming series; lists the next 1-3 ("<merchant> ~Rs X, due
    <relative>"); tap opens an Upcoming screen with the full list. All amounts
    via AmountText/formatRupeesFromMinor so redaction masks them. Slots near
    BudgetCard/WhereItWentCard on Home.
D-f Upcoming screen: each row = merchant, typical amount, cadence, last paid,
    next due (relative). Optional session-only "Not recurring" to hide a false
    positive for this app run (no DB). >= 48 dp targets, a11y labels.
D-g typicalAmountMinor is an ESTIMATE (median) — label it "~Rs X" / "about",
