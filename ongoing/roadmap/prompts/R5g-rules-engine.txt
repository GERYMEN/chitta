CHITTA-REF-APP FEATURE → TRACKER SCHEMA v2 → ENGINE BEHAVIOUR (implement all 27):
 1 sender list per issuer      → `senders` (DLT header IDs) — exact match
   on the header after parseSender strips operator prefix/suffix.
 2 sender_regexes              → `sender_regexes` (JS regex strings) —
   tried only when no exact sender hit; first issuer wins.
 3 global OTP blacklist        → top-level `blacklist_regex` — tested on
   the normalized body BEFORE any pattern; hit = label 'otp', stop.
 4 pattern order (sort_UID)    → `sort_UID` ascending; ties by array
   order. First match wins.
 5 obsolete                    → `obsolete: true` — pattern still MATCHES
   (old SMS in a re-scan must parse) but is skipped for NEW SMS dated
   after `obsolete_after` (epoch ms) when present.
 6 preProcessor                → `preprocessor: [{find, replace, flags}]`
   at issuer and/or pattern level — applied in order (issuer first) to a
   COPY of the normalized body before that pattern's regex.
 7 reparse                     → `reparse: true` — after a match, remove
   the matched span and run the issuer's patterns again on the rest
   (max 3 records per SMS). Each record gets its own sourceReferenceHash
   suffix `#n` (n ≥ 2) so dedupe stays per record.
 8 sms_type                    → transaction | statement | notice |
   balance | event | ignore. transaction → ParsedSmsTransaction;
   statement/notice/balance → SmsNonTransaction (R5b/R6/R8 inputs);
   event → typed SmsEvent (stored nowhere yet; returned for future use);
   ignore → label 'failed' or `ignore_reason`, no record.
 9 account_type                → bank | credit_card | debit_card | wallet
   | prepaid | loan | pay_later | utility | insurance. Mapping to Tracker
   AccountType: bank→bank, debit_card→bank (+pan_kind debit_card for
   alias suggestion, R5d T3b), credit_card→credit_card, wallet/prepaid/
   pay_later→other, loan/utility/insurance→ non-transaction only.
10 data_fields.amount/pan/pos/note/date/account_balance/
   outstanding_balance/available_limit/min_due_amount/currency/
   network_reference_id/counterparty_pan → `{group_id}` (int or int[] —
   first non-empty group wins) or `{value}` (constant). Amount strings →
   paise via toMinor (Indian + western grouping). pan → lastFour (4
   digits) or lastDigits (3 digits, `min_digits: 3`). network_reference_id
   → ref_digest only (R5d hashing), never stored raw.
11 date formats                → `date: {group_id, formats:[{format,
   use_sms_time}]}` or `{use_sms_time: true}`. Tokens: yyyy yy MM MMM dd
   d HH mm ss, quoted literals. Parse in Asia/Kolkata. Result is used
   only when within [smsDate − 45 days, smsDate + 1 day]; otherwise SMS
   time (chitta-ref-app also falls back to SMS time for stale dates). A
   format `'immediate'` literal = SMS time.
12 transaction_type            → debit | credit (direction).
13 money_kind (TRACKER-ONLY)   → spend | income | refund | transfer |
   card_payment | atm | wallet_load | emi | interest. Feeds R5d
   `moneyHint`; everything except spend/income/interest is HELD from
   auto-approve until R5e converts it.
14 transaction_type_rule       → `{group_id, rules:[{value, txn_type,
   pos_override, set_no_pos, acc_type_override, money_kind_override}]}` —
   `value` is a regex tested (i) against the group; first hit applies its
   overrides.
15 pos_type_rules              → `{group_id, rules:[{value, category,
   income_flag_override}]}` — first hit sets the category hint (mapped:
   salary→cat-salary; others → merchant-rule key only, never a new
   category) and may force income true/false.
16 network_reference type rule → `network_reference_id.type_rule:
   {rules:[{value, ref_type}]}` (upi|imps|neft|rtgs) — kept as a
   derived field for the refund/duplicate rankers.
17 set_no_pos / pos value      → `pos: {value, set_no_pos}` — set_no_pos
   = merchant 'Unknown' is acceptable for confidence (no penalty).
18 account_name_override       → pattern/issuer `account_name_override` —
   display name proposed in New accounts found.
19 set_account_as_expense      → issuer/pattern flag — for wallets/

20 create_txn / show_notification → per pattern; create_txn false = parse
   for balance/bill only; show_notification reserved (no notifications
   exist yet).
21 incomplete / deleted + chaining (enable_chaining, chaining_rule:
   {parent_selection:[{parent_field, child_field, match_type, match_value}],
   parent_match:{parent_override, child_override}, parent_nomatch:
   {child_override}}) → match_type exact | delta (ms) | value | none |
   same_or_alias | exact_if_present. Parent search: live + pending rows
   within the largest delta (default 1 h), same issuer unless a selector
   says otherwise. TRACKER SEMANTICS (never auto-delete): child_override

22 misc_information.get_balance → issuer `misc_information.get_balance:
