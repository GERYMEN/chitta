D-b AUTO tags are DERIVED (virtual), NOT stored: from paymentMethod ->
    '#UPI' (upi), '#Card' (card), '#Cash' (cash), '#Bank' (bank); 'other' -> no
    auto tag. A pure helper autoTagsFor(transaction) -> string[]. They show as
    non-removable chips and are filterable. CUSTOM tags are user-created, stored
    in tags/transaction_tags, add/remove on the detail screen. Tag names
    normalized (trim + lower for the key) so '#Food' and 'food' do not duplicate;
    display keeps the user's casing.
D-c Detail: a tags row showing auto chips (muted, non-removable) + custom chips
    (removable) + an "Add tag" affordance (pick existing or type new). A receipt
    section: if receipt_path set + file exists, show a thumbnail (tap -> full
    view); else an "Attach receipt" button opening the system photo picker.
    "Remove receipt" deletes the sandbox file + clears receipt_path (5 s Undo
    restores the path only if the file still exists).
D-d Filter by tag: add a tag chip/section to the Transactions filters
    (transactionFilters predicate: a transaction matches a selected tag if it is
    a custom tag on it OR an auto tag it derives). Persist the selected tag with
    the other R5j persisted filters; Reset clears it.
D-e Receipt files live in files/receipts/ (app-internal). Served via a
    FileProvider for the in-app viewer only. Deleting a transaction deletes its
    receipt file. No receipt bytes in any backup, export, audit, or log.
