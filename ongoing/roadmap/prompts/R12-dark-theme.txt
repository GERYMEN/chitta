MIGRATION PATTERN (apply consistently):
- colors.ts exports `lightColors` and `darkColors` (same keys; the existing
  object becomes lightColors) + a `ColorTokens` type = typeof lightColors.
- A ThemeProvider (src/theme/ThemeProvider.tsx) holds the resolved mode and
  palette; useColors() returns the active ColorTokens; useTheme() returns
  { colors, spacing, radii, typography, shadows, mode }. spacing/radii/
  typography/shadows do NOT change by mode (reuse as-is), but expose them through
  the hook too so files have ONE import.
- Component that used `import { colors } from theme` + a module-scope
  `const styles = StyleSheet.create({... colors.x ...})`: convert to a
  `const makeStyles = (c: ColorTokens) => StyleSheet.create({... c.x ...})`
  factory (module scope, pure) and inside the component
  `const c = useColors(); const styles = useMemo(() => makeStyles(c), [c]);`.
  Files that only use colors inline (no module-scope StyleSheet) just call
  useColors() in the component. A file that uses colors OUTSIDE any component
  (pure non-React module, e.g. a token used in a constant) must take the palette
  as a parameter or move the usage into a component — FLAG any that cannot.
- Do NOT change spacing/radii/typography values or any non-color styling.
