DEFAULTS (orchestrator; owner may override later):
D-a Migration 14 (additive, never edit old ones): ALTER TABLE accounts ADD
    COLUMN sms_balance_minor INTEGER (nullable) + ADD COLUMN sms_balance_at
    INTEGER (nullable, epoch ms of the SMS). Map both in account.mapper.ts and
    add to account.types.ts (sms_balance snapshot fields, optional). Backup
    (backup.tables.ts) lists BOTH columns with sinceVersion 14; restoring an
    old backup without them still works.
D-b Snapshot write (syncSms): when a synced SMS (a) matches an existing account
    via the R5d key logic AND (b) carries balanceMinor from the reader, write
    sms_balance_minor = balanceMinor and sms_balance_at = the SMS timestamp —
    but ONLY IF that SMS is newer than the stored sms_balance_at (latest wins;
    never overwrite a newer snapshot with an older SMS). The snapshot is a FACT
    about the account independent of txn approval, so it is written even when
    the txn itself is held/pending. Never store SMS body/sender. A sync with no
    balance-bearing matched SMS leaves the snapshot untouched.
D-c Pure difference helper in src/domain/accounts/ : reconcileBalance(account)
    -> { trackedMinor, bankMinor, diffMinor, asOf } | null. trackedMinor =
    calculateBalance(account); bankMinor = sms_balance_minor; diffMinor =
    trackedMinor - bankMinor; asOf = sms_balance_at. Returns null when there is
    no snapshot. "Reconciled" = diffMinor === 0. Unit-test sign both ways.
D-d UI (AccountsScreen card + account detail): when a snapshot exists show
    "Bank SMS: Rs X as of <time>"; when diffMinor !== 0 also show
    "Difference Rs Y" (Y = abs(diffMinor), with a sign/direction word). All
    amounts via AmountText/formatRupeesFromMinor so redaction masks them. No
    row shown when there is no snapshot.
D-e Actions on a non-zero difference:
    (1) "Use bank balance" -> sets the EXISTING user anchor
        (balance_anchor_minor = bankMinor, balance_anchor_at = now) via the
        account repository; calculateBalance then reconciles. Audited (D-h).
        Show a one-line effect explanation before applying.
    (2) "Add missing transaction" -> opens the manual Add Record form PRE-FILLED
        with amount = abs(diffMinor), account = this account, kind inferred from
        sign (tracked < bank -> income; tracked > bank -> expense), saved as a
        PENDING item (never auto-recorded). User can edit before saving.
    (3) "Dismiss" -> hides the difference for THIS snapshot only (persist a
        dismissed-at keyed to the current sms_balance_at); a newer snapshot
        (newer sms_balance_at) re-surfaces the difference. Dismiss is not a
        correction and writes no anchor.
D-f R6 NEVER silently changes a balance. Only the explicit "Use bank balance"
    tap writes an anchor; "Add missing" creates a normal pending item through
    the existing approval flow. The snapshot itself changes no balance.
D-g Clock via useNow for "as of <time>" relative formatting so it stays live on
    focus. Reuse existing relative-time helpers if present; do not add a date
    library.
D-h Audit: reuse the existing anchor/settings audit for "Use bank balance" if
    one already exists (check audit.types.ts first); only if none fits, add
    balance_anchor_set (metadata: accountId, amountMinor — ids/numbers only).
    The snapshot write is high-frequency derived data and is NOT audited.
    "Add missing" rides the existing detected/added audit of the created item.
    Add any new type to AuditEventType + AuditMetadata + activityFeed labels.
