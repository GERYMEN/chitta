TASK — generalize `calculateBalance` (same file, same exported name — "do
not fork it" per the skill):

```ts
export function calculateBalance(
  account: Pick<Account, 'openingBalanceMinor' | 'balanceAnchorMinor' | 'balanceAnchorAt'>,
  transactions: ReadonlyArray<Pick<Transaction, 'status' | 'type' | 'amountMinor' | 'accountId' | 'occurredAt'>>,
  accountId: string,
): number {
  const anchorMinor = account.balanceAnchorMinor ?? account.openingBalanceMinor;
  const anchorAtMs = account.balanceAnchorAt ? Date.parse(account.balanceAnchorAt) : -Infinity;

  return transactions
    .filter(
      t =>
        t.accountId === accountId &&
        affectsBalance(t) &&
        Date.parse(t.occurredAt) > anchorAtMs,
    )
    .reduce((balance, t) => (t.type === 'income' ? balance + t.amountMinor : balance - t.amountMinor), anchorMinor);
}
```
(This is a strong hint at the exact shape, not a mandate to copy verbatim —
implement it correctly, add types properly, but the logic above is exactly
what's required: when `balanceAnchorAt` is `null`, `anchorAtMs` is
`-Infinity`, so EVERY transaction's `occurredAt` is `> -Infinity` and gets
included — this is byte-for-byte the same result as today's behavior for
every existing account. When an anchor IS set, only transactions strictly
AFTER `balanceAnchorAt` count, starting from `balanceAnchorMinor` instead
of `openingBalanceMinor`. Transactions dated before/at the anchor are
simply excluded from the sum here — this function doesn't need to do
anything else with them (the skill says they stay visible/editable
elsewhere in the UI, which is unaffected by this pure function).
