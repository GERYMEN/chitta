TASK — create `src/features/sms-sync/normalizeAccountKey.ts`:

Export:
```ts
export const ACCOUNT_KEY_NORMALIZER_VERSION = 1; // bump + migrate on any future change to the logic below

export interface AccountKey {
  bankCanonical: string;   // e.g. 'hdfc', 'federal', 'sbi', 'unknown'
  accountKind: AccountType; // 'bank' | 'credit_card' | 'upi' (never cash/other from SMS)
  lastFour: string;        // '' sentinel for unidentified, NEVER null/undefined
  normalizerVersion: number; // always ACCOUNT_KEY_NORMALIZER_VERSION
}

export function normalizeAccountKey(body: string): AccountKey;

/** Stable string form for use as a Map key / DB composite key equality check. */
export function accountKeyToString(key: AccountKey): string; // e.g. `${bankCanonical}:${accountKind}:${lastFour}`
```

Implementation requirements:

1. **Bank alias map** — a `Record<string, string>` (or similar) mapping many
   real-world variants to one canonical lowercase bank id. At minimum cover
   these aliases (case-insensitive matching against the message body),
   each mapping to its canonical id:
   - `hdfc` ← "HDFC", "HDFC Bank", "HDFCBK" (a sender-ID-style token that
     can appear standalone in some message formats)
   - `federal` ← "Federal Bank", "Federal", "FEDBNK"
   - `sbi` ← "SBI", "State Bank of India", "SBI Card", "SBICRD" — THIS IS
     THE SPECIFIC CASE THAT WAS BROKEN BEFORE: "SBI Card ending 5368" and
     "SBI A/C 5368" must both resolve to canonical `'sbi'`, not fall
     through to unknown. Check for the alias token "SBI" on its own
     (word-boundary, case-insensitive) BEFORE requiring an adjacent word
     "Bank" — that is the structural fix for the bug.
   - `icici` ← "ICICI", "ICICI Bank", "ICICIB"
   - `axis` ← "Axis", "Axis Bank", "AXISBK"
   - `kotak` ← "Kotak", "Kotak Mahindra", "KOTAKB"
   - `pnb` ← "PNB", "Punjab National Bank"
   - `boi` ← "Bank of India", "BOI"
   - `canara` ← "Canara Bank", "Canara"
   - `union` ← "Union Bank", "Union Bank of India"
   - `yes` ← "Yes Bank", "YESBNK"
   - `idfc` ← "IDFC", "IDFC First", "IDFC FIRST Bank"
   You do not need every Indian bank — this is a v1 alias map, extensible
   later. Document in the file's own comment that it's not exhaustive and
   new banks fall back to `'unknown'` (not a crash, not a wrong bank).
   Check the MOST SPECIFIC alias match first (e.g. "IDFC First Bank"
   before a bare "IDFC" fallback) so longer/more specific tokens win.
   No match at all → `bankCanonical: 'unknown'`.
2. **accountKind** — reuse the same precedence already proven correct in
   `smsParser.ts` (credit card wording wins over bank/account wording,
   which wins over a bare UPI fallback) — you may literally copy those two
   regexes (`CREDIT_CARD_PATTERN`, `BANK_ACCOUNT_PATTERN`) into this new
   file since this phase doesn't touch `smsParser.ts`, or factor them into

   actual logic between the two without a reason.
3. **lastFour extraction across varied formats** — must correctly extract
   the last 4 digits from ALL of these real-world formats (test every one):
   `XX1859`, `*1859`, `X1859`, `XXXX1859`, `a/c ending 1859`, `a/c X1859`,
   `card ending 8123`, `A/C *7302`, `Acct XX1234`. Reuse/extend the
   existing `LAST_FOUR_PATTERN` idea from `smsParser.ts` if it already
   covers most of these — verify with tests, don't assume. Return `''`
   (empty string, the sentinel — NEVER `null`/`undefined`) when truly
   unextractable (a bare UPI-only message with no account reference at

4. **Determinism**: the SAME input body must always produce the exact same

5. `accountKeyToString` must produce a string suitable as both a JS `Map`
