      caveat), `date` (double, epoch millis). Always close the cursor

T4. SMS parser (pure TS, fully unit-testable, no native/device dependency) —
    create `src/features/sms-sync/smsParser.ts`:
    - `parseSmsMessage(msg: SmsMessage): ParsedSmsTransaction | null` where
      `ParsedSmsTransaction = { type: TransactionType; amountMinor: number;
      merchantName: string; occurredAt: string; confidenceScore: number;
      sanitizedPreview: string; sourceReferenceHash: string }`.
    - Heuristic v1 rules (keep it genuinely simple, regex-based, document
      your exact patterns in the output log):
      - Reject (`return null`) if body matches an OTP/promotional pattern
        (e.g. contains `OTP`, `one time password`, case-insensitive) or
        doesn't contain any currency/amount pattern at all.
      - Detect amount via a pattern like
        `/(?:rs\.?|inr|₹)\s*([\d,]+\.?\d{0,2})/i`, strip commas, parse to
        paise via `Math.round(parseFloat(x) * 100)`.
      - Detect direction: `expense` if body matches
        `/debited|spent|paid|withdrawn/i`; `income` if it matches
        `/credited|received|deposited/i`. If neither matches, `return
        null` (ambiguous, don't guess).
      - Extract a merchant name with a best-effort pattern like
        `/(?:at|to|from)\s+([A-Za-z0-9&.\-_ ]{3,30})/i` (trim result);
        fall back to `'Unknown'` if no match — still create the
        transaction (a pending review with "Unknown" merchant is better
        than silently dropping a real detected transaction; the user fixes
        it via Edit).
      - `occurredAt`: `new Date(msg.date).toISOString()`.
      - `confidenceScore`: start at `0.9` if direction + amount + merchant
        all matched cleanly, `0.6` if merchant fell back to `'Unknown'`,
        `0.4` if amount format was ambiguous (e.g. no decimal places found
        but a number was present) — your call on exact thresholds, just be
        reasonable and document them.
      - `sourceReferenceHash`: `` `sms-${msg.id}-${msg.date}` ``.
      - `sanitizedPreview`: built from already-parsed fields only, per the
        ground facts above — never raw `msg.body`.
    - `parseSmsMessage` must NEVER include `msg.address` or `msg.body` in
      its return value, only derived/sanitized fields.

T5. Sync orchestration — create
    `src/features/sms-sync/syncSms.ts` exporting an async
    `syncSms(): Promise<{ scanned: number; created: number; skipped: number

      throw/return a result the caller can show a clear message for (e.g. a

    - Reads up to e.g. 200 inbox messages via `readInbox`, runs each through

      actually added, `skipped` = scanned minus created, whether from
      parse-rejection or dedup).
