Design requirements for the dialog:
- New shared component in `src/shared/ui/Dialog/` exported from
  `src/shared/ui/index.ts`, alongside Button/Card/Chip/BottomSheet.
- Built with RN `Modal` (transparent, fade) + scrim + a centered surface.
  Do NOT add reanimated/gesture-handler/any new npm dependency (they were
  deliberately removed this project — see STATE.md).
- Use ONLY existing theme tokens from `src/theme`
  (colors: surfaceContainerLowest/surface, onSurface, onSurfaceVariant,
  error/errorContainer, primary, obsidian…; radii: lg/xl; spacing;
  typography: headlineSm for title, bodyMd/bodyLg for message; shadows).
  Match the look of existing Cards/BottomSheet — light surface, rounded,
  same font family. No hard-coded hex colors.
- Action buttons reuse the existing `Button` component and its variants
  (`'primary' | 'brand' | 'ghost' | 'destructive'`): Cancel → ghost,
  Delete → destructive, neutral confirm (OK / Open Settings / Go to
  Accounts) → primary or brand. Buttons ≥48dp touch target.
- Optional leading icon per dialog (e.g. trash for delete, alert/shield for
  permission) via the existing `Icon` from `src/shared/icons`.
- API: make migration easy — an imperative `showDialog({ title, message,
  icon?, actions: [{ label, variant?, onPress? }] })` backed by a tiny
  Zustand store + a single `<DialogHost />` mounted once at app root
  (find where RootNavigator / providers are mounted, e.g. App.tsx or
  src/app/*). Tapping any action closes the dialog then runs its onPress.
  Android hardware back = dismiss (same as Cancel); tapping the scrim =
  dismiss for non-destructive dialogs. If Zustand store selectors return
  objects/arrays use `useShallow` (STATE.md explains the infinite-loop
  crash this prevents).
- Keep ToastAndroid toasts as they are (user asked for them in Phase 5);
  this phase is about Alert dialogs only.
